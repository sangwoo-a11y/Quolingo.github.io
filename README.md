# Quolingo

뮤니, 코, 타스와 함께하는 말씀 읽기와 QT. 빌드 없이 GitHub Pages에서 실행하는 정적 웹사이트입니다.

## 실행과 검증

```sh
python3 -m http.server 8080
```

별도 설치나 외부 성경 API는 필요하지 않습니다. 구약 39권과 신약 27권, **총 66권·1,189장·31,102절**의 개역한글 본문을 포함합니다. 본문 출처, 고정 리비전, 체크섬, 사용 안내는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 있습니다. 기존 여호수아 본문과 기록용 시편 발췌도 보존합니다.

```sh
node --check app.js
node --check progress.js
node --check chapters.js
node --check old-testament.js
node --check new-testament.js
node --test tests/*.test.cjs
```

본문 테스트는 구약·신약의 모든 장 수, 절 수, 본문 추출 체크섬, 기록 ID의 고유성을 확인합니다. 진행 테스트는 세 가지 완료 조건과 이전 완료 기준의 보존과 일요일 휴식일의 연속학습 처리를 검증합니다.

Playwright와 Chromium이 설치된 환경에서는 서버를 실행한 뒤 `node tests/browser.cjs`로 실제 브라우저 흐름을 검증할 수 있습니다. `node tests/interaction.cjs`는 실제 버튼 누름·빛남, 키보드 조작, 이동 취소, 4·5·6주 달력과 320–1440px 화면의 캐릭터 배치를 확인합니다. `TEST_URL`과 `CHROMIUM_PATH`로 주소와 브라우저 경로를 바꿀 수 있습니다. QT용·읽기용 권의 독립 선택, QT/말씀 전환, 기록 분리와 중복 방지, 이전 기록, 완료 조건과 일요일 제외, 목표 변경 후 과거 완료 보존, 백업, 캐릭터별 팔 동작, 모바일 화면과 하단 여백을 확인합니다.

## 말씀 여행

첫 화면의 초록색 배너 아래 **QT / 말씀** 버튼으로 방식을 선택합니다. 각 모드의 배너와 장 목록에는 계정에서 해당 용도로 고른 권을 표시합니다. 이번 달 날짜 버튼만 표시하며, 날짜와 요일을 버튼 아래에 적습니다. 월요일–일요일 단위로 색상을 바꾸고 주 사이를 선으로 나눕니다. 각 주 경로의 중간 날짜 옆에 코 → 뮤니 → 타스를 반복 배치하고, 일부 주에는 두 캐릭터가 함께 인사합니다. 오른쪽·왼쪽으로 번갈아 표시합니다. 오늘도 다른 날짜와 같은 버튼 모양이며, 미래 날짜는 비활성화합니다. 지난 날짜의 기록도 작성할 수 있습니다.

- **QT**: 날짜 → 장과 시작·끝 절 선택 → 읽기 → 관찰 → 해석 → 적용. 해석에서는 말씀과 관찰 내용을, 적용에서는 말씀과 해석 내용을 다시 볼 수 있습니다. 같은 날짜·장의 범위별 기록을 따로 저장합니다. 겹치는 절은 그날의 QT 읽기량에 한 번만 집계하며, 원형 게이지는 읽은 절 수를 반영합니다.
- **말씀**: 날짜 → 장 선택 → 장 전체 읽기 → **이 장 읽기 완료**. 완료한 장은 같은 날짜에 한 번만 집계합니다. 다른 날짜에 다시 읽으면 그날의 읽기량으로 집계합니다. 다음 장으로 바로 이어 읽을 수 있습니다. 장 읽기는 여러 권을 합산하며 **QT에서 읽은 절과 완전히 별도**입니다. 원형 게이지와 체크는 그날의 말씀 목표 달성 여부를 표시합니다.
- 오른쪽 **연속학습** 아래에서 오늘 읽은 장과 목표 장 수를 확인합니다. 모바일에서는 QT/말씀 버튼 아래에 표시합니다.
- 읽기 현황의 다이아몬드 **그동안 읽은 말씀**은 날짜별 QT 읽은 절의 누적 합계입니다. 상단 다이아몬드는 오늘의 QT 읽은 절 수입니다. 말씀 모드의 누적 장 수는 별도로 표시합니다.
- 뮤니와 타스는 각자 손을 흔들고, 코는 날개를 흔들며 가볍게 뜁니다. 몸과 팔을 분리해 서로 다른 주기로 움직입니다. 날짜 버튼은 두꺼운 하단 그림자와 밝은 표면으로 입체감을 표현하며, 마우스를 올리면 버튼 면이 살짝 내려가고, 클릭하면 더 깊게 눌린 상태에서 빛이 지나간 뒤 화면을 엽니다. 모바일에서는 터치하는 동안 깊은 눌림을 표시합니다. 기기의 동작 줄이기 설정을 켜면 멈춥니다. 완료 표시는 두꺼운 SVG 체크이며, 맨 아래 날짜 뒤에도 넉넉한 여백을 둡니다.

캐릭터 그림은 제공된 참고 이미지로 제작한 투명 PNG입니다. 왼쪽부터 뮤니(여우), 코(병아리), 타스(곰)입니다. `assets/character-parts.png`의 몸·팔 영역을 조합해 애니메이션을 표시하며, 기존 `assets/friends.png`도 원본 참고용으로 보관합니다.

## 계정과 하루 완료 조건

**계정**에서 **큐티말씀(QT용)**과 **말씀(장 읽기용)**을 각각 성경 66권 중에서 선택합니다. 예를 들어 QT는 마태복음, 장 읽기는 창세기로 지정할 수 있습니다. 매일 말씀 목표(1–1,189장), 하루 완료 조건, 일요일 QT 끄기를 설정합니다. 이 설정은 이름을 입력하지 않아도 즉시 저장됩니다. 이름(최대 20자)과 프로필 캐릭터는 **프로필 저장**으로 저장합니다. 처음 설정은 두 모드 모두 여호수아, 하루 1장, 완료 조건 ‘QT만’입니다.

| 하루 완료 조건 | 일반적인 날 | 일요일 QT를 끈 일요일 |
| --- | --- | --- |
| QT와 말씀 목표 모두 | QT 완료 + 장 목표 달성 | 장 목표 달성 |
| QT만 | QT 완료 | 휴식일 |
| 말씀 목표만 | 장 목표 달성 | 장 목표 달성 |

휴식일은 주간 달력에 `–`로 표시하고, 완료한 날 수에는 더하지 않으며 연속학습도 끊지 않습니다. 일요일 QT를 꺼도 말씀 읽기는 가능합니다. 완료한 날은 오른쪽 해당 요일에 체크합니다. 오늘이 아직 미완료라면 어제까지의 연속학습을 표시합니다.

삭제된 ‘QT와 말씀 목표 중 하나’를 사용하던 프로필은 ‘QT와 말씀 목표 모두’로 전환하며, 과거에 저장된 날짜별 완료 기준은 보존합니다. 목표와 완료 조건을 바꾸면 오늘부터 적용합니다. 기록을 시작한 날의 기준을 보관해 과거 완료를 유지하며, 이전 버전에서 완료한 QT 날도 기존 완료로 인정합니다. 날짜 계산은 한국 시간(Asia/Seoul)을 사용합니다.

## 기록과 백업

서버 로그인 없이 현재 브라우저의 localStorage에 저장합니다. 기기 간 동기화는 없으며 브라우저 데이터를 삭제하면 기록도 지워집니다.

- `quolingo-chapters-v2`: 날짜·장·범위별 QT `sessions`와 읽은 절. 이전 장별 기록은 전체 장 범위 세션으로 보존하며 원래 필드도 유지합니다.
- `quolingo-reading-v1`: 날짜별 완료한 장 ID와 해당 날짜의 목표·완료 기준. QT와 별도입니다.
- `quolingo-profile-v1`: 프로필, QT 권 `qtBookId`와 읽기 권 `readingBookId`, 목표·완료 조건·일요일 설정. 이전의 공통 권 `bookId`는 두 모드의 초기 선택으로 옮기며, 기록은 변경하지 않습니다.
- `quolingo-journal-v1`: 이전 버전 기록을 삭제하지 않고 나의 묵상과 연속학습에 반영합니다.

**나의 묵상 / 계정 → 전체 기록 백업**으로 모든 기록과 설정을 version 4 JSON 파일로 다운로드합니다. 백업 가져오기는 아직 지원하지 않습니다. 저장 실패 시 알림을 표시합니다.

## GitHub Pages 배포

Settings → Pages → Source를 **GitHub Actions**로 설정합니다. `main`에 푸시하면 `.github/workflows/pages.yml`이 본문 파일과 화면 파일을 함께 배포합니다. 상대 경로이므로 프로젝트 페이지 주소에서도 실행합니다.

Actions가 `waiting for github-pages deployment approval`이라고 표시하면 환경 승인이 필요한 상태입니다. 저장소 업로드만으로 사이트 갱신이 완료되는 것은 아니며, 해당 실행의 환경 승인 후 배포 성공 여부를 확인해야 합니다.
