# Quolingo

뮤니, 코, 타스와 함께하는 말씀 읽기와 QT. 빌드 없이 GitHub Pages에서 실행하는 정적 웹사이트입니다.

## 실행과 검증

```sh
python3 -m http.server 8080
```

별도 설치나 외부 성경 API는 필요하지 않습니다. 구약 39권과 신약 27권, **총 66권·1,189장·31,102절**의 개역한글 본문을 포함합니다. 본문 출처, 고정 리비전, 체크섬, 사용 안내는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 있습니다. 기존 여호수아 본문과 기록용 시편 발췌도 보존합니다.

```sh
node --check app.js
node --check progress.js
node --check sharing.js
node --check cloud.js
node --check chapters.js
node --check old-testament.js
node --check new-testament.js
node --test tests/*.test.cjs
```

본문 테스트는 구약·신약의 모든 장 수, 절 수, 본문 추출 체크섬, 기록 ID의 고유성을 확인합니다. 진행 테스트는 세 가지 완료 조건과 이전 완료 기준의 보존과 일요일 휴식일의 연속학습 처리를 검증합니다. 공유 테스트는 선택한 날짜·장절 표시·항목 순서와 적용 내용의 명시적 포함 여부를 확인합니다.

Playwright와 Chromium이 설치된 환경에서는 서버를 실행한 뒤 `node tests/browser.cjs`로 실제 브라우저 흐름을 검증할 수 있습니다. `node tests/interaction.cjs`는 실제 버튼 누름·빛남, 키보드 조작, 이동 취소, 4·5·6주 달력과 320–1440px 화면의 여백을 고려한 캐릭터 배치를 확인합니다. `TEST_URL`과 `CHROMIUM_PATH`로 주소와 브라우저 경로를 바꿀 수 있습니다. QT용·읽기용 권의 독립 선택, QT/말씀 전환, 기록 분리와 중복 방지, 이전 기록, 완료 조건과 일요일 제외, 목표 변경 후 과거 완료 보존, 저장된 기록, 캐릭터별 팔 동작, 모바일 화면과 하단 여백을 확인합니다. `node tests/activity.cjs`는 월별 달력과 날짜별 상세, 권별 누적, 오늘·과거 기록 취소와 연속학습 반영, 저장 실패 시 기록 보존, 모바일 로고와 화면 폭을 검증합니다. `node tests/navigation.cjs`는 터치로 장 제목 선택, 완료 토글, 완료 전 장 이동, 모바일 다이아몬드 누적 집계와 이동 없음, 브라우저 뒤로가기·앞으로가기, 초안 복원, QT 단계별 진행과 통합 절 수를 확인합니다. `node tests/history.cjs`는 목표 상향·완료 조건 변경 후 달성 기록과 일요일 휴식일 보존, 새 날짜의 새 기준, 저장 실패 복구와 명시적인 읽기 취소를 검증합니다. `node tests/journal.cjs`는 완료 시점의 다이아몬드와 첫날 연속학습, 범위별·이전 기록 삭제, 겹치는 절의 중복 방지, 저장 실패 시 기록 보존을 검증합니다. `node tests/sharing.cjs`는 기기의 공유·복사 기능을 모의 처리해 실제 전송 없이 미리보기, 적용 포함/제외, 취소·오류, 과거 기록 공유, 저장된 기록 보존을 검증합니다.

## 홈

첫 화면의 배너 아래 **QT / 말씀** 버튼으로 방식을 선택합니다. 각 모드의 배너와 장 목록에는 계정에서 해당 용도로 고른 권을 표시합니다. 이번 달 날짜 버튼만 표시하며, 날짜와 요일을 버튼 아래에 적습니다. 월요일–일요일 단위로 색상을 바꾸고 주 사이를 선으로 나눕니다. 각 주 경로의 중간 날짜 옆에 코 → 뮤니 → 타스를 반복 배치하고, 일부 주에는 두 캐릭터가 함께 인사합니다. 오른쪽·왼쪽에 주별로 번갈아 표시합니다. 좌우가 바뀌는 주에는 S자 경로도 반대로 굽혀 캐릭터가 넓은 바깥 여백에 자리하도록 합니다. 캐릭터를 조금 크게 보여주고, 버튼과 최소 28px 간격을 유지하며, 창 크기가 바뀌어도 다시 배치합니다. 메뉴바 아래에는 세 캐릭터가 함께 인사합니다. 오늘도 다른 날짜와 같은 버튼 모양이며, 미래 날짜는 비활성화합니다. 지난 날짜의 기록도 작성할 수 있습니다.

- **QT**: 날짜 → 장과 시작·끝 절 선택 → 읽기 → 관찰 → 해석 → 적용. 해석에서는 말씀과 관찰 내용을, 적용에서는 말씀과 해석 내용을 다시 볼 수 있습니다. 읽은 말씀 다시 보기는 기본적으로 접혀 있고 눌러서 펼칠 수 있습니다. 이전·다음 버튼으로 단계를 옮기며, 모바일 브라우저의 뒤로가기·앞으로가기도 이전 화면과 작성 내용을 복원합니다. 새로고침해도 현재 화면을 유지합니다. 같은 날짜·장의 범위별 기록을 따로 저장합니다. 겹치는 절은 그날의 QT 읽기량에 한 번만 집계하며, QT 원형 게이지는 읽기·관찰·해석·적용을 마칠 때 25%씩 채워집니다. 작성 중인 초안만으로는 다음 단계 완료로 집계하지 않습니다. 기존 기록은 저장된 읽기·작성 내용과 완료 여부로 단계를 복원합니다.
- **말씀**: 날짜 → 장 선택 → 장 전체 읽기 → **이 장 읽기 완료**. 완료한 장은 같은 날짜에 한 번만 집계합니다. 다른 날짜에 다시 읽으면 그날의 읽기량으로 집계합니다. 읽기 완료 여부와 관계없이 이전·다음 장으로 이동할 수 있습니다. 장 제목을 누르면 장 선택을 다시 엽니다. **이 장 읽기 완료**를 다시 누르면 되돌릴 수 있으며, 목표·연속학습·누적 장 수에 바로 반영됩니다. 저장 실패 시 기존 기록을 유지합니다. 장 읽기는 여러 권을 합산하며 **QT에서 읽은 절과 완전히 별도**입니다. 원형 게이지와 체크는 그날의 말씀 목표 달성 여부를 표시합니다.
- 오른쪽 **연속학습** 아래에서 오늘 읽은 장과 목표 장 수를 확인합니다. 모바일에서는 QT/말씀 버튼 아래에 표시합니다.
- 다이아는 완료한 QT 범위의 절과 말씀 모드에서 완료한 장의 전체 절을 합산해 얻으며, 아이템 구매 금액을 뺀 **사용 가능한 다이아**를 표시합니다. QT에서 읽기 단계를 넘기거나 초안을 작성할 때는 늘어나지 않고, 묵종을 완료했을 때 반영합니다. PC·모바일 상단과 기록 화면의 **그동안 읽은 말씀**은 구매와 관계없이 누적 읽은 절 수를 표시합니다. 같은 날 같은 장은 각 모드 안에서 한 번만 집계하고, 두 모드에서 각각 읽었다면 두 읽기량을 합산합니다. 사용 가능한 잔액은 꾸미기 화면에서 확인합니다. 말씀 모드의 누적 장 수는 별도로 표시합니다. 모바일 달력은 정사각형에 가까운 날짜 칸으로 높이를 줄입니다. 월별 달력에서 완료, QT 완료, 읽은 장 수를 확인하고 날짜를 선택해 그날 읽은 권·장을 볼 수 있습니다. 장 제목을 누르면 읽기 화면을 열고 완료 버튼으로 취소할 수 있습니다. 이전 달도 조회할 수 있습니다. **기록** 메뉴의 **말씀 읽기 현황**에는 여러 권의 누적 장 수를 표시합니다. 권 이름을 누르면 읽은 장 번호를 펼쳐 확인하며, 다른 날에 반복한 장은 횟수도 표시합니다. 다른 날짜에 같은 장을 다시 읽으면 누적에 다시 더합니다. 모바일 상단에도 quolingo 로고를 표시합니다.
- 뮤니와 타스는 각자 손을 흔들고, 코는 날개를 흔들며 가볍게 뜁니다. 몸과 팔을 분리해 서로 다른 주기로 움직입니다. 날짜 버튼은 두꺼운 하단 그림자와 밝은 표면으로 입체감을 표현하며, 마우스를 올리면 버튼 면이 살짝 내려가고, 클릭하면 약 4px 이내로 가볍게 눌린 상태에서 빛이 지나간 뒤 화면을 엽니다. 모바일에서는 터치하는 동안 깊은 눌림을 표시합니다. 기기의 동작 줄이기 설정을 켜면 멈춥니다. 완료 표시는 두꺼운 SVG 체크이며, 맨 아래 날짜 뒤에도 넉넉한 여백을 둡니다.

캐릭터 그림은 제공된 참고 이미지로 제작한 투명 PNG입니다. 왼쪽부터 뮤니(여우), 코(병아리), 타스(곰)입니다. `assets/character-parts.png`의 몸·팔 영역을 조합해 애니메이션을 표시하며, 기존 `assets/friends.png`도 원본 참고용으로 보관합니다.

## 계정과 완료 조건

**성경 번역본**에서 개역한글·개역개정·새번역을 선택하고 **저장**을 누르면 QT와 말씀 읽기에 적용됩니다. 개역한글은 사이트 안에서 읽고, 개역개정·새번역은 선택한 권·장·시작 절을 대한성서공회 공식 페이지로 새 탭에서 엽니다. 읽은 후 Quolingo로 돌아와 묵종 작성과 장 완료를 이어갑니다. 해석·적용 단계의 접힌 말씀 다시 보기에서도 같은 번역본을 엽니다. 기존 기록·다이아·연속학습은 유지하고 번역본 선택도 계정에 동기화합니다. 개역개정·새번역 공식 페이지는 인터넷 연결이 필요합니다.

`node --test tests/bible-reading.test.cjs`로 66권의 공식 링크 매핑을, `node tests/bible-reading.cjs`로 번역본 저장·QT/말씀 연결·접힌 말씀 다시 보기·새 탭 동작을 확인합니다. 공식 페이지는 테스트에서 가로채며 실제 본문을 요청하지 않습니다.

**계정**에서 **QT(QT용)**과 **말씀(장 읽기용)**을 각각 성경 66권 중에서 선택합니다. 예를 들어 QT는 마태복음, 장 읽기는 창세기로 지정할 수 있습니다. 매일 말씀 목표(1–1,189장), 완료 조건, 일요일 QT 끄기를 설정합니다. 이름, 성경 선택, 목표, 완료 조건, 일요일 QT, 색상, 캐릭터 변경은 모두 **저장**을 눌러야 저장·적용됩니다. 저장하지 않고 화면을 이동하거나 새로고침하면 기존 설정을 유지합니다. **기본 색**에서 살구·노랑·베이지·하늘·분홍·보라를 고르면 계정 화면에서 미리 볼 수 있으며, **저장**을 눌렀을 때 적용·저장됩니다. 저장하지 않고 화면을 이동하거나 새로고침하면 기존 색으로 돌아갑니다. 배너와 주요 버튼, 선택 상태, QT의 절 수 표시, 묵종 제목, 링크와 포커스, 카드·입력란 배경에 적용하며 주별 색상은 선택한 색을 기준으로 서로 다르게 표시합니다. 저장한 색상은 로그인 계정에 자동 동기화됩니다. 이름(최대 20자)과 프로필 캐릭터는 **저장**으로 저장합니다. 연속학습 일수·읽은 절 수·완료 일수는 기록에서 확인합니다. 처음 설정은 두 모드 모두 여호수아, 하루 1장, 완료 조건 ‘QT만’입니다.

| 완료 조건 | 일반적인 날 | 일요일 QT를 끈 일요일 |
| --- | --- | --- |
| QT와 말씀 목표 모두 | QT 완료 + 장 목표 달성 | 장 목표 달성 |
| QT만 | QT 완료 | 휴식일 |
| 말씀 목표만 | 장 목표 달성 | 장 목표 달성 |

휴식일은 주간 달력에 `–`로 표시하고, 완료한 날 수에는 더하지 않으며 연속학습도 끊지 않습니다. 일요일 QT를 꺼도 말씀 읽기는 가능합니다. 오늘 완료한 날도 즉시 연속학습에 포함하며, 첫 완료일은 1일로 표시합니다. 완료한 날은 오른쪽 해당 요일에 날짜 버튼과 같은 두꺼운 SVG 체크를 표시합니다. 오늘이 아직 미완료라면 어제까지의 연속학습을 표시합니다.

삭제된 ‘QT와 말씀 목표 중 하나’를 사용하던 프로필은 ‘QT와 말씀 목표 모두’로 전환하며, 과거에 저장된 날짜별 완료 기준은 보존합니다. 목표와 완료 조건을 바꾸면 오늘의 새 목표에 적용하되, 이미 달성한 완료·연속학습은 당시 기준으로 유지합니다. 과거 날짜와 일요일 휴식일의 기준도 보관합니다. 읽기 완료 취소나 묵종 삭제 시에는 남은 기록이 당시 달성 기준을 충족하는지 다시 계산합니다. 이전 버전에서 완료한 QT 날도 기존 완료로 인정합니다. 날짜 계산은 한국 시간(Asia/Seoul)을 사용합니다.

## 로그인과 동기화

구글 로그인, 현재 기기 로그아웃과 자동 동기화를 지원합니다. 수동 동기화와 기존 기록 가져오기 버튼은 표시하지 않습니다. 로그인 전 기기 기록은 계정 기록과 별도로 보관하며, 로그아웃하면 다시 볼 수 있습니다. 계정 캐시와 로그인 전 기록을 분리해 다른 사람의 기록이 섞이지 않도록 합니다. 여러 기기에서 서로 다른 항목을 수정하면 합치고, 같은 항목을 다르게 수정하면 두 내용을 비교해 선택합니다. 선택 전 두 내용은 해당 계정의 기기에 백업합니다. 변경 직후, 온라인 복구와 화면 복귀, 30초 간격으로 동기화합니다.

서버에서는 인증된 소유자의 행만 읽게 하고 버전 비교 저장 함수로 오래된 쓰기를 거부합니다. Supabase SDK 2.118.0은 저장소에 고정해 외부 CDN 없이 불러옵니다. 친구 기능의 화면은 아직 추가하지 않았으며 개인 기록은 소유자에게만 공개합니다.

`node --test tests/cloud.test.cjs`는 계정 캐시 분리·오프라인 수정·동시 변경·충돌·가져오기·계정 전환을 확인합니다. `node tests/cloud-browser.cjs`는 외부 로그인 없이 구글 OAuth 요청, 자동 저장과 수동 버튼 없음, 계정 화면·충돌 비교·로그아웃·재로그인을 검증합니다. SQL의 소유자 접근과 버전 비교는 [설정 안내](supabase/SETUP.md)의 PostgreSQL 테스트로 확인합니다.

## 꾸미기와 다이아

**꾸미기** 메뉴에서 배경 3종(80·100·140 다이아), 소품 3종(45·55·65 다이아), 프로필 테두리 3종(55·75·85 다이아)을 미리 보고 구매합니다. 기존 완료 기록도 **1절 = 1다이아**로 반영합니다. QT는 묵종을 완료해야, 말씀 모드는 장을 완료해야 다이아를 얻습니다. 잔액은 완료한 QT 절 수와 읽은 장의 절 수 합계에서 구매한 아이템 가격을 뺀 값입니다. 꾸미기는 사용 가능한 잔액을 표시하고, PC·모바일 상단과 기록은 구매와 관계없이 누적 읽은 절 수를 표시합니다.

구매 확인 후 구매와 적용을 한 번에 저장하며 저장 실패 시 차감하지 않습니다. 중복 구매는 막고, 보유 아이템 적용·해제에는 다이아를 쓰지 않습니다. 소품은 코·뮤니·타스별로 따로 구매하고 적용합니다. 한 캐릭터의 소품을 바꿔도 다른 캐릭터의 소품은 유지합니다. 이전 버전에서 구매한 공용 소품은 세 캐릭터의 사용 권한과 기존 사용액을 유지하며 추가 차감하지 않습니다. 반짝 별 배지는 동일한 구매가의 선글라스로 교체됩니다. 배경은 홈의 꾸민 공간에, 소품은 홈·주별 캐릭터·메뉴 캐릭터에, 테두리는 프로필에 반영합니다. 미리보기는 저장하지 않습니다. 구매 내역과 적용 상태는 프로필의 `decorations`에 저장되어 기존 계정 동기화를 따릅니다. 게스트와 다른 계정의 보유 아이템은 분리됩니다.

읽기 취소·묵종 삭제 시 적립량도 줄지만 구매한 아이템은 유지합니다. 사용액이 적립량보다 크면 잔액은 0이며 다음 적립에서 부족분을 먼저 채웁니다. 같은 기록을 취소하고 다시 완료해도 다이아가 중복 적립되지 않습니다. 이미 판매한 아이템 ID의 가격은 유지하며 가격을 바꿀 때는 새 ID를 사용합니다.

`node --test tests/customization.test.cjs`는 구매·잔액·소유권·동기화 병합을, `node tests/customization.cjs`는 모바일 구매/적용, 저장 실패 복구, 새로고침, 읽기 취소와 반응형 화면을 검증합니다. `node tests/cloud-browser.cjs`는 외부 요청 없이 구매 내역의 자동 동기화와 계정 분리를 확인합니다.

## 묵종 공유

묵종 완료 화면의 **묵종 공유하기**에서 공유 창을 엽니다. **나의 묵종**의 완료 기록에는 **이어쓰기 · 공유하기 · 묵종 삭제**가 표시됩니다. 삭제 확인 후 해당 범위의 묵종만 삭제하며, 다이아몬드·연속학습·달력을 다시 계산합니다. 다른 묵종 범위와 말씀 모드의 읽기 기록은 유지합니다. 날짜, 말씀의 장·절 표시, 관찰, 해석 순서로 미리보기를 표시합니다. 성경 본문 텍스트는 미리보기·공유·복사 내용에서 제외합니다. **적용 내용도 함께 공유**는 공유 창을 열 때마다 기본으로 선택되며, 해제하면 적용 내용을 제외합니다. 저장된 묵종 자체는 바뀌지 않습니다. 과거 기록을 공유하면 해당 묵종 날짜를 표시합니다.

휴대폰 등의 공유 메뉴에서 카카오톡을 비롯한 설치된 앱을 선택할 수 있습니다. 공유 메뉴를 지원하지 않는 브라우저에서는 **내용 복사하기**로 복사해 원하는 앱에 붙여넣습니다. 공유 메뉴가 있는 브라우저에서도 **내용 복사**를 사용할 수 있으며, 공유 취소 시에는 복사하거나 재전송하지 않습니다. 자동 복사가 허용되지 않으면 미리보기 내용을 선택해 직접 복사할 수 있게 합니다. 별도 카카오 앱 키나 서버는 사용하지 않습니다.

## 기록 저장

로그인하지 않으면 현재 브라우저의 localStorage에 저장합니다. Supabase 연결 후 구글로 로그인하면 계정별로 캐시를 분리하고 프로필·QT·말씀 읽기·이전 기록을 동기화합니다. 프로젝트 설정이 비어 있으면 기존 기기 저장을 유지하고 로그인 버튼은 비활성화합니다. 실제 연결 순서는 [Supabase 설정 안내](supabase/SETUP.md)에 있습니다. 브라우저 데이터를 삭제하면 기기에만 있던 기록은 지워집니다.

- `quolingo-chapters-v2`: 날짜·장·범위별 QT `sessions`와 읽은 절. 이전 장별 기록은 전체 장 범위 세션으로 보존하며 원래 필드도 유지합니다.
- `quolingo-reading-v1`: 날짜별 완료한 장 ID와 해당 날짜의 목표·완료 기준. QT와 별도입니다.
- `quolingo-profile-v1`: 프로필, QT 권 `qtBookId`와 읽기 권 `readingBookId`, 목표·완료 조건·일요일 설정. 이전의 공통 권 `bookId`는 두 모드의 초기 선택으로 옮기며, 기록은 변경하지 않습니다.
- `quolingo-journal-v1`: 이전 버전 기록을 삭제하지 않고 나의 묵종과 연속학습에 반영합니다.

전체 기록 백업 버튼은 표시하지 않습니다. 저장 실패 시 알림을 표시하며, 로그인한 기록은 연결 복구 후 자동 동기화합니다.

## GitHub Pages 배포

Settings → Pages → Source를 **GitHub Actions**로 설정합니다. `main`에 푸시하면 `.github/workflows/pages.yml`이 본문 파일과 화면 파일을 함께 배포합니다. 상대 경로이므로 프로젝트 페이지 주소에서도 실행합니다.

Actions가 `waiting for github-pages deployment approval`이라고 표시하면 환경 승인이 필요한 상태입니다. 저장소 업로드만으로 사이트 갱신이 완료되는 것은 아니며, 해당 실행의 환경 승인 후 배포 성공 여부를 확인해야 합니다.

## Chrome 앱 설치와 바로가기

**계정 → Quolingo 앱**의 **앱 설치**를 누릅니다. 설치 요청을 지원하지 않는 상태에서는 **설치 및 바로가기**가 표시되며, 누르면 기기별 방법을 펼칩니다.

- 컴퓨터 Chrome: 주소창의 설치 아이콘을 누르거나, ⋮ → 전송, 저장 및 공유 → 바로가기 만들기를 이용합니다.
- Android Chrome: ⋮ → 홈 화면에 추가 → 설치를 선택합니다.
- iPhone·iPad: 공유 메뉴에서 홈 화면에 추가를 선택합니다.

아이콘은 코·뮤니·타스가 함께 있는 그림입니다. 192/512px 앱 아이콘, Android 마스크용 아이콘, Apple 홈 화면 아이콘, 파비콘을 제공합니다. `manifest.webmanifest`의 상대 경로와 앱 범위는 GitHub Pages 프로젝트 경로에서도 유지됩니다.

서비스 워커는 공개된 앱 파일과 성경 본문만 저장하며, 온라인에서는 먼저 새 파일을 요청합니다. 로그인·데이터베이스 요청과 OAuth 콜백 URL은 캐시에 저장하지 않습니다. 앱을 한 번 연 뒤에는 연결이 끊겨도 저장된 화면과 성경 본문을 열 수 있습니다. 기기 기록의 저장·계정 동기화 방식은 기존과 같습니다. 배포할 때 `index.html`의 파일 버전과 `sw.js`의 캐시 버전을 함께 갱신합니다.

`node tests/pwa.cjs`는 실제 Chromium의 설치 가능 여부, 프로젝트 경로의 manifest·아이콘·서비스 워커, 색상 미리보기와 프로필 저장 후 적용, 설치·취소·설치 안내, 새 파일 갱신과 오프라인 말씀 읽기를 확인합니다. 운영체제의 실제 설치 창과 사용자 계정 로그인은 테스트에서 실행하지 않습니다.
